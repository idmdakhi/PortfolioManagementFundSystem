# کارمزدها

## قواعد محاسبه
فرمول‌ها در `BusinessRules.md` (بخش ۱ و ۳). پارامترها روی خود دوره ذخیره می‌شوند تا دوره‌های بسته با نرخ همان زمان بمانند:

| پارامتر | معنی |
| --- | --- |
| `fixed_rate` | سود ثابت مشتری، درصد سالانه (از «سود بانکی» در تنظیمات؛ دورهٔ بعد از همان می‌گیرد) |
| `mgmt_rate` | کارمزد ثابت صندوق (٪ از ارزش بازار برای هر دوره، تقسیم بر ۱۲ مثل اکسل) |
| `excess_rate` | سهم سبدگردان از سود بالاتر از سود ثابت (صندوق) |
| `fee_cap` | سقف کارمزد، به واحد ۱۰٬۰۰۰٬۰۰۰ ریال |
| `discount` | تخفیف ریالی |
| `mgmt_rate_2`, `excess_rate_2` | معادل برای حساب شخصی |

رند: کف به مضرب ۱۰۰٬۰۰۰ ریال برای کارمزد صندوق. سقف برای دوره‌های غیر ۱۲ ماهه در کد صندوق متناسب نمی‌شود (مقدار سقف همان است)؛ برای حساب شخصی سقف همان `fee_cap` است. (← `todo.md` T-12: تصمیم دربارهٔ تناسب سقف.)

## زمان شناسایی و تسویه
کارمزد در پایان هر دوره **محاسبه** می‌شود و «باقی‌مانده» تا تسویه از NAV کم می‌شود. روش‌های تسویه (`fee_receipts.method`):

| روش | اثر |
| --- | --- |
| `record` | فقط ثبت سابقهٔ دریافت؛ بر محاسبه اثر ندارد |
| `cash` | پرداخت نقدی از صندوق؛ ارزش بازار کم می‌شود؛ سود و کارمزد بدون تغییر؛ NAV تغییری نمی‌کند |
| `units` | صدور واحد به سبدگردان (`transactions.kind='fee'`)؛ پولی خارج نمی‌شود؛ NAV تغییری نمی‌کند |
| `settle` | تسویهٔ خودکار هنگام بستن دوره |

هر سه روش با تست‌های «fee settlement» تأیید شده‌اند: NAV ثابت می‌ماند و جمع سود خالص نفرات برابر سود صندوق است.

## کنترل‌ها
- مبلغ تسویهٔ نقدی/واحدی نباید از «باقی‌ماندهٔ کارمزد» بیشتر باشد.
- پرداخت نقدی و صدور واحد فقط در دورهٔ قابل ویرایش.
- حذف صدور واحد، تراکنش مرتبط را هم حذف می‌کند و فقط وقتی مجاز است که واحد سبدگردان منفی نشود.

## کارمزد شخصی
`scope='personal'`: فقط سابقه (اثری روی NAV ندارد).
