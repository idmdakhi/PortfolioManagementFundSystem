# نصب، راهنمای کاربری و بازیابی

## نصب (ویندوز / لینوکس)
پیش‌نیاز: Node.js ۲۴ LTS (نسخهٔ ۲۲ هم اجرا می‌شود ولی رسمی نیست).
```
npm install
copy .env.example .env        # لینوکس: cp
node ace generate:key
node ace codegen
node ace migration:run
node ace db:seed
npm run dev
```
ورود: `ADMIN_EMAIL` / `ADMIN_PASSWORD` از `.env` (پیش‌فرض `admin@example.com` / `ChangeMe-123`). مدیر **فقط یک‌بار** ساخته می‌شود؛ اجرای دوبارهٔ `db:seed` گذرواژهٔ موجود را تغییر نمی‌دهد.

**بلافاصله بعد از اولین ورود گذرواژه را عوض کنید:**
```
node ace user:password admin@example.com
```
گذرواژه مخفی تایپ می‌شود (در تاریخچهٔ shell نمی‌ماند)، حداقل ۱۲ نویسه، و گذرواژه‌های پیش‌فرض/رایج پذیرفته نمی‌شود. در حالت production اگر `ADMIN_PASSWORD` ضعیف یا پیش‌فرض باشد، seed ساخته‌شدن مدیر را رد می‌کند.

### تولید (production)
```
NODE_ENV=production
npm run build
cd build && npm ci --omit=dev
node bin/server.js
```
`DB_PATH` را به مسیری خارج از پوشهٔ کد بدهید و از آن پشتیبان بگیرید.

### متغیرهای محیطی
| نام | معنی |
| --- | --- |
| `APP_KEY` | کلید رمزنگاری (با `generate:key`) |
| `DB_PATH` | مسیر فایل SQLite؛ پیش‌فرض `database/seeders/db.sqlite3` |
| `SESSION_DRIVER` | `cookie` (پیش‌فرض) یا `memory` |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | مدیر اولیه هنگام `db:seed` (فقط اگر هنوز وجود نداشته باشد) |

## راهنمای کاربری کوتاه
- **ثبت صدور/ابطال**: «تراکنش‌ها». NAV خالی بماند = NAV دوره.
- **تقسیم یک مبلغ بین چند نفر**: «حرکت‌ها» ← مبدأ/مقصد ← روش تقسیم.
- **ارزش‌گذاری**: «ارزش‌گذاری» ← ارزش روز کل صندوق را وارد کنید؛ NAV و سهم‌ها بلافاصله به‌روز می‌شوند.
- **کارمزد**: «کارمزدها» ← انتقال با صدور واحد، یا پرداخت نقدی، یا ثبت سابقه.
- **بستن دوره**: «تنظیمات» ← «بستن دوره». ابتدا «تطبیق» را ببینید؛ با خطا بسته نمی‌شود.
- **اصلاح اشتباه**: ویرایش یا حذف در دورهٔ باز؛ برای دورهٔ بسته، مدیر کلید «ویرایش دوره‌های بسته» را موقتاً روشن کند و بعد خاموش کند. همهٔ تغییرها در «سابقه» می‌مانند.
- **گزارش مشتری**: صفحهٔ سرمایه‌گذار ← «گزارش» ← چاپ یا ذخیره PDF.
- **خروجی CSV**: صفحهٔ تراکنش‌ها ← «خروجی CSV» (برای Excel).

## پشتیبان‌گیری
- از منوی «پشتیبان»: خروجی JSON کامل (بدون کاربران). هفتگی و قبل از هر بستن دوره بگیرید.
- یا فایل `DB_PATH` را در حالت خاموش بودن سرور کپی کنید.
- پشتیبان‌ها حاوی اطلاعات مالی افراداند؛ رمزگذاری/نگهداری امن با شماست. در گیت نگذارید.

## بازیابی
1. «پشتیبان» ← انتخاب فایل JSON ← بازیابی. عملیات اتمیک است و اگر خطا شود چیزی تغییر نمی‌کند.
2. نسخهٔ قبل از بازیابی خودکار در `tmp/backups/pre-restore-*.json` می‌ماند.
3. بعد از بازیابی، صفحهٔ «تطبیق» را ببینید.
4. **آزمون بازیابی** هر ماه: بازیابی روی یک نصب جدا و مقایسهٔ NAV و جمع واحدها با نسخهٔ اصلی.

## رفع خطا
| نشانه | علت/راه‌حل |
| --- | --- |
| `Missing environment variable "APP_KEY"` | `node ace generate:key` |
| «درخواست تکراری» | همان فرم تا ۱۵ ثانیه پیش با موفقیت ثبت شده؛ فهرست را ببینید |
| «تلاش‌های ناموفق زیاد» | ۱۰ دقیقه صبر کنید |
| تطبیق خطا نشان می‌دهد | جزئیات هر بررسی را بخوانید؛ برنامه چیزی را خودکار تغییر نمی‌دهد |
| `no such table` | `node ace migration:run` |
