# راهبرد تست

```
node ace test                 # همه
node ace test unit            # محاسبات و ابزارها (بدون دیتابیس)
node ace test integration     # دیتابیس واقعی SQLite (فایل جدا)
npx tsc --noEmit              # نوع‌ها
```

- تست‌ها با `.env.test` اجرا می‌شوند: `DB_PATH=tmp/test.sqlite3`، `APP_KEY` ثابت تست. **هرگز** به دیتابیس واقعی دست نمی‌زنند؛ مجموعهٔ `integration` اگر مسیر دیتابیس شامل «test» نباشد اجرا نمی‌شود و هر بار فایل را از نو و با مهاجرت‌ها می‌سازد.
- CI (`.github/workflows/test.yaml`): Node 22 و 24، بدون نیاز به `.env`.

## آزمون دستی دودی (قبل از انتشار)
۱. نصب تازه با `DB_PATH` جدا، ورود، ثبت صدور، ثبت دوباره (پیام تکراری)، ابطال بیش از موجودی (رد).
۲. سود تقسیمی در دورهٔ بسته (رد). نرخ منفی در تنظیمات (پیام زیر فرم). CSV در Excel (فارسی درست).
۳. صفحهٔ «تطبیق» و «سابقه». بستن دوره با تطبیق سالم.
این سناریوها در این ویرایش با curl روی نصب تازه اجرا و تأیید شدند.

## قاعدهٔ توسعه
هر اشکال رفع‌شده یک تست رگرسیون دارد. تغییر فرمول بدون به‌روزرسانی تست مرجع اکسل (و توضیح تفاوت در `BusinessRules.md`) پذیرفته نیست.
