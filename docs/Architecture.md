# معماری

## پشته

| لایه | فناوری |
| --- | --- |
| وب | AdonisJS 7 (Node.js ≥ 22؛ توصیه‌شده ۲۴) |
| رابط | Edge templates سمت سرور + CSS ساده + Alpine.js؛ راست‌چین و فارسی |
| دیتابیس | SQLite با `better-sqlite3` از طریق Lucid |
| اعتبارسنجی | VineJS + میان‌افزار نرمال‌سازی ورودی فارسی |
| احراز هویت | نشست (کوکی HttpOnly، ۲ ساعت) + نقش `admin` / `viewer` |
| تاریخ | ذخیره میلادی (ISO)، نمایش شمسی (`jalaali-js`) |
| تست | Japa (`node ace test`) |

## لایه‌ها و جهت وابستگی

```
views (edge)  ←  controllers  →  services  →  models (Lucid) → SQLite
                     ↑                ↑
                middleware       fund_calculator (خالص، بدون دیتابیس)
```

- `app/services/fund_calculator.ts`: **محاسبات خالص**. به دیتابیس، HTTP و فایل وابسته نیست؛ با تست واحد مقابل اعداد اکسل کنترل شده است.
- `app/services/fund_state.ts`: `loadState()` همهٔ جدول‌ها را می‌خواند و گزارش هر دوره (صندوق + هر سرمایه‌گذار) را می‌سازد. **تنها منبع عددهای نمایش‌داده‌شده**؛ داشبورد، گزارش، صفحهٔ سرمایه‌گذار و چاپ همه از همین‌جا می‌آیند.
- `app/services/*`: `valuation` (ارزش پایهٔ دوره)، `splitter` (تقسیم مبلغ گروهی)، `jalali`، `options`، `period_guard` (قفل دورهٔ بسته)، `backup`، و سرویس‌های امنیتی/کنترلی (`audit`, `write_lock`, `reconcile`, `login_throttle`, `csv`).
- `app/middleware/*`: احراز هویت، نقش، نرمال‌سازی ورودی، بارگذاری گزینه‌ها، **قفل نوشتن، محافظ درخواست تکراری، ثبت حسابرسی**.
- `app/controllers/*`: فقط ورودی را بررسی و سرویس‌ها را صدا می‌زنند.
- `database/migrations`: تنها منبع ساختار جدول‌ها. `database/schema.ts` را Lucid از روی migrationها تولید می‌کند؛ دستی ویرایش نکنید.

## اصول

1. **هیچ مقدار مشتقی ذخیره نمی‌شود.** موجودی واحد، سرمایه، NAV، سود و کارمزد هر بار از تراکنش‌ها و دفتر ارزش‌گذاری محاسبه می‌شوند. (استثنا: ستون‌های «legacy» دوره که با دفتر ارزش‌گذاری همگام می‌شوند، `Valuation.md`.)
2. **مبلغ = ریال صحیح** (`bigInteger`)؛ **واحد = `double`** مانند اکسل. رند کردن در هر قلم انجام می‌شود (`Math.round`).
3. **همهٔ نوشتن‌ها پشت یک قفل سراسری** اجرا می‌شوند تا «بررسی ← ثبت» بین درخواست‌ها نشکند (`Security.md`، D-05).
4. **عملیات گروهی اتمیک‌اند**: همه یا هیچ (`db.transaction`).
5. **دورهٔ بسته برای همیشه قفل است**: تراکنش، حرکت گروهی، سود تقسیمی، کارمزد، ارزش‌گذاری و حساب شخصی آن قابل ثبت، ویرایش یا حذف نیست (کلید «ویرایش دوره‌های بسته» حذف شد). هر تغییر در دورهٔ باز در سابقهٔ حسابرسی می‌ماند.
6. **هر تغییر ردپا دارد** (`audit_logs`).

## بستن دوره (`periods.close`)

۱. کنترل تطبیق مالی؛ با هر اختلاف «خطا» بستن رد می‌شود.
۲. در یک تراکنش دیتابیس: وضعیت دوره بسته، کارمزد باقی‌مانده به‌صورت `fee_receipts(method='settle')` تسویه، دورهٔ بعد با ارزش ابتدایِ «پس از کسر کارمزد» ساخته، ورودی‌های `close`/`open` در دفتر ارزش‌گذاری ثبت، و حساب شخصی هر نفر به دورهٔ بعد منتقل می‌شود.

## پشتیبان

- خروجی JSON کامل (بدون جدول `users` و بدون هش گذرواژه) و بازیابی اتمیک؛ پیش از بازیابی، نسخهٔ فعلی در `tmp/backups/` ذخیره می‌شود.
- فایل دیتابیس SQLite را هم می‌شود مستقیم کپی کرد (`Operations.md`).
